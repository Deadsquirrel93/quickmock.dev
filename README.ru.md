# Quickmock

> Поднимите HTTP мок-эндпоинт за 30 секунд. Без регистрации, без конфиг-файлов, без SDK. Только URL.

🇬🇧 **English version:** [README.md](README.md)

**[quickmock.dev →](https://quickmock.dev)**

Quickmock — бесплатный сервис для разработчиков, которым нужен фейковый HTTP-эндпоинт *прямо сейчас*: разблокировать фронтенд, симулировать сторонний API, воспроизвести нестабильный edge case. Вставляете тело ответа, выбираете код статуса — получаете публичный URL, который ведёт себя ровно так, как вы сказали.

**Без трекеров. Без аналитики. Без аккаунтов.** Подробности — в разделе [Приватность](#приватность).

## Быстрый старт (30 секунд)

1. Откройте **[quickmock.dev](https://quickmock.dev)**
2. Вставьте тело ответа (JSON, XML, plain text — что угодно).
3. Нажмите **Создать мок**.
4. Скопируйте сгенерированный URL: `https://quickmock.dev/m/abc123`
5. Используйте где угодно:

```bash
curl https://quickmock.dev/m/abc123
```

Всё. Никаких аккаунтов, никаких API-ключей, никакого ожидания подтверждения email.

> ⚠️ **Не вставляйте настоящие секреты.** Моки публичны — любой, у кого есть URL, может прочитать тело ответа. Никогда не помещайте в мок реальные API-ключи, токены доступа, пароли или продакшен-данные.

## Возможности

- **Создание мока в одной форме** — метод, тело, статус, заголовки, задержка.
- **Все HTTP-методы** — `GET`, `POST`, `PUT`, `PATCH`, `DELETE` или `ANY`.
- **Произвольные заголовки ответа** — `Content-Type`, CORS, что угодно.
- **Имитация медленного API** — фиксированная задержка или случайный джиттер в диапазоне мин–макс.
- **Имитация нестабильного API** — последовательность ответов по кругу (1-й → 200, 2-й → 500, снова — классический тест ретраев) и настраиваемая доля ошибок, подменяющая ответ для N% запросов.
- **Переключатель CORS** — один чекбокс добавляет разрешающий CORS-пресет без credentials и отвечает на preflight `OPTIONS`, чтобы мок можно было вызывать из браузерного JS с любого origin.
- **Авто-истечение моков** — TTL от 1 часа до 30 дней.
- **Именованные варианты и условные ответы** — нужный ответ можно выбрать по имени либо определить по методу, пути, query, заголовкам и JSON-полям запроса.
- **Multi-route workspace** — до 50 маршрутов method + path под одним slug; маршруты можно сгенерировать импортом OpenAPI 3.x в JSON/YAML.
- **Приватный живой инспектор и экспорт конфига** — запросы приходят по SSE после проверки admin-токена; сохранение тела и IP отправителя отключается раздельно. Конфиг можно выгрузить и загрузить как JSON.
- **Copy as cURL** — в один клик копируется готовая команда для теста.
- **Динамические токены** — вставь `{{faker.uuid}}`, `{{now.iso8601}}` и т.п. в тело; на каждый запрос подставляются свежие значения. См. [Динамические токены](#динамические-токены).
- **Эхо запроса** — токены `{{request.*}}` возвращают входящий запрос обратно: метод, путь, IP, query-параметры, заголовки, тело целиком или JSON-поле из него.
- **Гайды по сценариям** — в `/guide` готовые рецепты: тесты ретраев, нестабильные/медленные API, инспекция вебхуков, фейковые данные и не только.
- **Готовые шаблоны** — [`/templates`](https://quickmock.dev/templates): десять конфигураций мока в один клик (вебхуки Stripe/Shopify, push-события GitHub, discovery для OAuth2/OIDC, JWKS, ошибки по RFC 9457 и другое), у каждой — разбор payload'а и отличий от настоящего сервиса.
- **Admin-токен** — управляй моком с любого устройства: создание возвращает одноразовый токен. Изменение, удаление, очистка и чтение приватных логов требуют `Authorization: Bearer`; браузер обменивает токен на HttpOnly-сессию, ограниченную путём мока.
- **Без регистрации** — моки и их admin-токены хранятся в `localStorage` браузера; URL ответа остаётся публичным, управление и приватные логи защищены.
- **Двуязычный интерфейс** — английский и русский из коробки; планируются ещё языки.

## Динамические токены

Нужен разный ответ на каждый вызов вместо замороженного блоба? Вставь токен в тело ответа — Quickmock хранит шаблон как есть и подставляет свежее значение на каждый запрос. Неизвестные токены не трогаются, так что твой собственный template-синтаксис не пострадает.

```json
{
  "id": "{{faker.uuid}}",
  "name": "{{faker.name}}",
  "email": "{{faker.email}}",
  "created_at": "{{now.iso8601}}"
}
```

| Namespace   | Токены                                                                                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `faker.*`   | `name`, `firstname`, `lastname`, `username`, `email`, `phone`, `url`, `ipv4`, `uuid`, `int`, `bool`, `word`, `sentence`, `color`, `company`, `city`               |
| `now.*`     | `iso8601` (RFC 3339), `unix` (секунды), `unix_ms`, `date` (YYYY-MM-DD), `time` (HH:MM:SS), `rfc1123` (HTTP-дата)                                                  |
| `request.*` | `method`, `path`, `host`, `ip`, `query.<name>`, `header.<name>`, `body` (как есть, первые 16 КБ), `body.<json.путь.через.точку>` (например `body.user.name`, `body.items.0.sku`) |
| `mock.*`    | `url` — собственный базовый URL мока (`https://quickmock.dev/m/<slug>`), для тел ответа, которые должны ссылаться на себя                                          |

Токены `request.*` возвращают входящий запрос обратно в ответ, а `{{mock.url}}` называет сам мок — это то, что нужно полю `issuer` в OIDC-документе или ссылке `next` в пагинации: слаг появляется только после создания. Значения вставляются как есть — текст, похожий на токен, внутри query-параметра или поля тела повторно не разворачивается — и ничего дополнительно не сохраняется:

```json
{
  "echo_method": "{{request.method}}",
  "echo_id": "{{request.query.id}}",
  "echo_trace": "{{request.header.x-request-id}}",
  "echo_user": "{{request.body.user.name}}"
}
```

Полный список с описаниями также есть в форме создания мока под пунктом «Динамические токены».

## Приватность

Quickmock работает на энтузиазме, а не на рекламных деньгах. Сервис создан, чтобы быть полезным, а не собирать данные.

**Чего **не** делаем:**

- Никакой сторонней аналитики (Google Analytics, Plausible, Яндекс.Метрика — ничего).
- Никаких пикселей-трекеров.
- Никакого фингерпринтинга браузера.
- Никакого внешнего JavaScript, никаких CDN-библиотек — HTMX и Alpine.js раздаются с quickmock.dev.
- Никаких внешних шрифтов — только системные.
- Никакой рекламы, никогда.
- Никаких аккаунтов, никакого email-сбора, никаких рассылок.
- Данные не продаются и никому не передаются.
- Никаких сервисов сбора ошибок (Sentry/Bugsnag/etc.) по умолчанию. Если когда-нибудь добавим — это будет opt-in и явно описано здесь.

**Что **всё-таки** логируется, и зачем:**

| Данные                                | Зачем                                          | Срок жизни                                                                                              |
| ------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Ваш IP в Redis                        | Rate limiting (5000 запросов на IP за 8 часов) | 8 часов, потом удаляется                                                                                |
| IP создателя каждого мока             | Лимит «50 активных моков на IP»                | До удаления или истечения мока. В UI никогда не показывается.                                           |
| Запросы к вашим мокам                 | Это фича инспектора; сохранение тела и IP настраивается отдельно | До 100 последних на мок; удаляются при истечении мока; можно очистить в любой момент                    |
| Куки языка и инспектора               | Запомнить язык и открыть приватный инспектор после проверки токена | Язык: 1 год. Инспектор: до 30 дней, только для пути конкретного мока.                                   |
| Server-side логи запросов (stdout)    | Операционная отладка                           | По умолчанию ротация средствами systemd / Docker journal                                                |

Это весь список.

## Защита origin-сервера

Три механизма Quickmock завязаны на IP посетителя: лимит активных моков на адрес, rate limit
и блок-лист оператора. За CDN этот адрес не приходит в TCP-соединении — он приходит в
заголовке, а большинство очевидных заголовков дописываются, а не перезаписываются, и потому
подделываются клиентом.

Quickmock читает `CF-Connecting-IP`, который Cloudflare перезаписывает на каждом запросе, и
только когда непосредственный пир — наш собственный nginx (`internal/middleware/realip.go`).
Это обоснованно лишь пока origin не отвечает никому, кроме Cloudflare: иначе тот, кто нашёл
его адрес, подключается напрямую и объявляет себя любым IP — обходя все три механизма и заодно
подставляя невиновный адрес.

Поэтому origin принимает веб-трафик только из диапазонов Cloudflare, на двух независимых
уровнях: список разрешённых адресов в фаерволе, который еженедельно обновляет таймер, и
Authenticated Origin Pulls, где nginx требует клиентский TLS-сертификат Cloudflare. По
отдельности ни один из них не закрывает задачу.

В [**deploy/cloudflare/**](deploy/cloudflare/) лежат скрипты и подробный разбор: зачем нужен
каждый уровень, в каком порядке их включать, чтобы не уронить сайт, как синхронизация падает
безопасно и какие есть подводные камни — включая тот, на котором мы споткнулись: списки IP
Cloudflare не заканчиваются переводом строки, поэтому `cat` склеивает два диапазона в один
битый.

## Стек

- **Бэкенд:** Go 1.27+
- **Фронтенд:** HTMX + Alpine.js + Go-шаблоны (без Node.js и сборщика)
- **Хранилище:** PostgreSQL (моки, логи запросов) + Redis (rate limiting, эфемерное состояние)
- **Reverse proxy:** Nginx + Let's Encrypt
